# Telegram Bot Integration

Управление ботом через Telegram: уведомления о новых заказах с личными фильтрами, избранное, настройка конвейера администратором.

> Полное руководство по проекту, включая Telegram-слой, команды и callback-кнопки:
> [`MANUAL_RU.md`](MANUAL_RU.md), разделы 7–8.

---

## Поток работы

```
сбор заказов с 7 площадок
        ↓
фильтр категорий (Kwork-таксономия)
        ↓
скоринг + красные флаги
        ↓
┌──────────────────────────────────────────────┐
│  ВСЕ прошедшие фильтр заказы → Telegram      │
│  Для каждого: LLM-анализ + первое письмо     │
└──────────────────────────────────────────────┘
        ↓
[✅ Отправить]  [❌ Пропустить]
        ↓
outbox (dry-run) → одобрено → отправка
```

**Ключевое:** в Telegram приходят **все** заказы, прошедшие фильтр, а не только top-N. Порогов балла и совпадения навыков больше нет: скоринг задаёт только **порядок** показа (заказы без красных флагов и свежие — первыми). Для каждого заказа LLM анализирует задачу и генерирует первое письмо на основе навыков из `profile.yaml`.

Лимит `messaging.max_messages_per_cycle` (по умолчанию 50) ограничивает только количество **сгенерированных писем** за цикл. Заказы сверх лимита всё равно приходят — просто без письма.

## Роли: администратор и пользователь

| Возможности | Кто |
|---|---|
| Общие настройки конвейера: `/interval`, `/score`, `/platforms`, `/categories`, `/set`, `/reset` и весь `/settings` | **Супер-админ** (чаты из `TELEGRAM_ADMIN_CHAT_IDS`) |
| Личные настройки: `/filters` (биржи, рубрики, подкатегории, мин. цена), `/jobs [5\|10\|30]`, `/favorites` | **Любой одобренный пользователь** |

Личные фильтры хранятся в SQLite и влияют только на ленту самого пользователя: остальные подписчики получают заказы по своим фильтрам. Пустой фильтр = показывать всё, что собирает бот.

## Функционал

### 1. Уведомления о новых заказах
- Карточка заказа в формате эталона: иконка отрасли и бейдж «● Новый», заголовок,
  первые 2–3 строки описания с «Показать полностью ▾»
- Блоки «Бюджет» (сумма в валюте заказчика и тип цены) и «Срок выполнения»
- Блок «О заказчике» с метриками (рейтинг, доля найма, число заказов) —
  скрывается целиком, если площадка не раскрыла данных
- Строка «🌐 Биржа: {название} · ID заказа: #{id}» и время публикации
- Кнопки «🔗 Перейти на страницу заказа» / «🪄 Составить письмо-ответ с AI» /
  «♥ Выделить как понравившееся»
- Отдельное сообщение «💡 Полезно знать» — почему заказ подошёл под профиль

### 1a. AI-квиз «Письмо под заказ»
- Четыре шага: тон письма → на чём сделать акцент → говорить ли о деньгах →
  какой задать уточняющий вопрос
- На каждом шаге можно выбрать готовый вариант или прислать «✍️ Свой вариант»
- Готовое письмо показывается целиком с кнопками
  «✏️ Редактировать» / «📋 Скопировать» / «🔄 Перегенерировать»
- Черновик сохраняется в SQLite: кнопки работают и после рестарта бота

### 2. Управление сбором
- `/start` — приветствие и список команд; новый пользователь отправляет заявку на подписку
- `/status` — текущий статус pipeline (запущен/приостановлен), статистика последнего цикла
- `/pause` / `/resume` — приостановка и возобновление сбора
- `/interval N` — интервал между циклами, **600–3600 секунд**; меняет только супер-админ

### 3. Личные фильтры (каждый пользователь)
- `/filters` — меню личных фильтров: биржи, рубрики, подкатегории, мин. цена
- `/filters platforms` — выбор бирж (inline кнопки; пустой выбор = все)
- `/filters price 5000` — минимальная цена; заказы «по договорённости» проходят всегда
- `/filters reset` — сброс к «показывать всё»
- `/favorites` — избранные заказы (кнопка ♥ на карточке)

### 4. Общие фильтры (только админ)
- `/platforms` — включить/выключить платформы сбора (inline кнопки)
- `/categories` — рубрики и категории заказов, минимальная цена (inline меню)
- `/settings` — просмотр конфигурации

Порог `/minscore` удалён: заказы скрываются только личными фильтрами, а не баллом.

### 5. Ценообразование и профиль
- `/pricing` — выбор стратегии цены (inline кнопки): минимум / наценка / оценка LLM
- `/markup 1.15` — коэффициент наценки (можно и как процент: `/markup 15` = 1.15)
- `/minprice 8000` — минимальная приемлемая цена
- `/profile` — навыки, опыт и стиль письма

Изменения применяются к следующим циклам сразу. Они живут в памяти процесса;
для постоянного хранения отредактируйте `profile.yaml` и `config.yaml`.

### 6. Статистика и логи
- `/jobs [5|10|30]` — последние заказы по личным фильтрам: балл, бюджет, ссылка, кнопка ♥
- `/favorites` — избранные заказы
- `/stats` — статистика за 7 дней из SQLite (заказы, сообщения, отправки, отклонённые)
- `/logs` — последние ошибки из pipeline

### 7. Устойчивость сообщений
- Свободный текст (заголовки, описания, письма, ошибки) экранируется для Telegram Markdown.
- Сообщения длиннее лимита Telegram автоматически делятся на части; кнопки остаются на последней части.
- `/pause` останавливает только сбор; команды и inline-кнопки продолжают работать.

### 8. Меню и справка
- Кнопки **`/menu`** и **`/help`** закреплены под полем ввода и остаются видимыми
- `/menu` — компактный список всех команд по группам
- `/help` — справка по каждой команде с описанием
- `/help <команда>` — подробно по одной команде, с примерами: `/help jobs`
- Список всех команд также публикуется в меню Telegram (кнопка «/»)

## Настройка

### 1. Получите токен бота

Создайте бота через [@BotFather](https://t.me/BotFather):

```
/newbot
Имя: Freelance Bot
Username: your_freelance_bot

BotFather ответит токеном: 1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
```

### 2. Узнайте свой Chat ID

Напишите боту [@userinfobot](https://t.me/userinfobot) — он покажет ваш Chat ID (например, `123456789`).

Для группы:
1. Добавьте бота в группу
2. Отправьте любое сообщение
3. Откройте `https://api.telegram.org/bot<TOKEN>/getUpdates`
4. Найдите `chat.id` в ответе (отрицательное число для групп)

### 3. Настройте .env

Добавьте в `.env`:

```bash
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_ADMIN_CHAT_IDS=123456789,987654321  # Через запятую, если несколько админов
```

### 4. Проверьте токен без запуска polling

```bash
# getMe: проверяет токен и сеть до api.telegram.org
python -m freelance_bot.cli telegram-check

# Дополнительно отправляет тестовое сообщение админам
python -m freelance_bot.cli telegram-check --send-test

# Можно передать токен и chat id явно, не трогая .env
python -m freelance_bot.cli telegram-check --token "123:ABC" --chat-id 123456789 --send-test
```

Ожидаемый вывод:

```
✅ Токен валиден: @your_freelance_bot (id=1234567890, name='Freelance Bot')
✅ Тестовое сообщение отправлено: 123456789
```

`telegram-check` не запускает polling и не мешает уже работающему боту.

### 5. Запустите бота

```bash
# Локально (Windows)
$env:PYTHONIOENCODING='utf-8'
$env:FREELANCE_BOT_CONFIG='config.yaml'
python -m freelance_bot.cli telegram --interval 300 --top 10

# На VPS (systemd service)
sudo systemctl start freelance-bot-telegram.service
```

### Как приходят новые заказы

Каждый подходящий заказ показывается **один раз**. Факт показа сохраняется в
SQLite (`jobs.notified_at`), поэтому рестарт бота и повторные проходы не
присылают его снова. Первое письмо генерируется до отправки уведомления; если
письмо не удалось составить, заказ не помечается показанным и будет повторён в
следующем проходе. Лимит `/send drafts` откладывает лишние заказы на следующий
проход, а не показывает их без письма. Если в проходе нет новых подходящих
заказов, сообщение
«✅ Цикл завершён» не отправляется — проход выполняется в фоне и обновляет
только статистику.

показываются всегда — после обсуждения цена может устроить.

### Полная настройка из Telegram

Все параметры меняются командами и сохраняются в `var/runtime_settings.yaml`
(оверлей поверх `config.yaml` и `profile.yaml`). Файлы-исходники не
переписываются, поэтому комментарии и ручные правки остаются целы. После
рестарта сервиса значения из оверлея применяются автоматически.

| Команда | Что настраивает |
|---|---|
| `/settings` | обзор; `/settings runtime\|scoring\|categories\|messaging\|llm\|platforms\|profile\|skills\|prompt`; `/settings all` — полный YAML |
| `/platforms` | список, кнопки вкл/выкл, `/platforms add <name>`, `/platforms rm <name>`, `/platforms url <name> <url>`, `/platforms on\|off <name>` |
| `/categories` | двухуровневое меню: рубрика → категории; `/categories add\|rm <key>`, `/categories price 5000`, `/categories conf 0.35`, `/categories unknown include`, `/categories sub list\|add\|rm\|clear` |
| `/score` | **только супер-админ**: `/score penalty 0.35`, `/score freshness 18`, `/score show` — штраф красных флагов и свежесть; порогов балла больше нет |
| `/send` | `/send dry on\|off`, `/send approval on\|off`, `/send limit 6`, `/send delay 240`, `/send drafts 20`, `/send chars <platform> <n>`, `/send links <platform> on\|off` |
| `/llm` | `/llm model <name>`, `/llm base <url>`, `/llm key <ключ>`, `/llm temp 0.4`, `/llm tokens 900`, `/llm timeout 60`, `/llm on\|off`, `/llm fallback on\|off`, `/llm test` |
| `/llm provider` | `/llm provider list`, `add <имя> <url> <модель> [ключ]`, `use <имя\|default>`, `show <имя>`, `key <имя> <ключ>`, `nokey <имя> on\|off`, `header <имя> <Header> <value>`, `rm <имя>` |
| `/prompt` | `/prompt show`, `/prompt system <текст>`, `/prompt extra <текст>`, `/prompt reset [system\|extra\|all]`; без текста бот ждёт следующее сообщение |
| `/style` | `/style tone friendly`, `/style length short`, `/style emoji 0`, `/style portfolio on`, `/style questions off`, `/style banned add\|rm\|list` |
| `/skills` | `/skills add\|rm <навык>`, `/skills add2\|rm2`; подкоманды `match\|exclude` удалены вместе с порогом совпадения |
| `/profile` | `/profile name Иван`, `/profile years 5`, `/profile location Москва`, `/profile summary` (текст следующим сообщением) |
| `/pricing` | кнопки стратегии, `/pricing rate 2500`, `/pricing price on\|off` |
| `/set`, `/get` | любой параметр по dotted-пути: `/set runtime.dry_run false`, `/get scoring.red_flag_penalty` |
| `/reload` | перечитать `config.yaml`/`profile.yaml` с диска |
| `/reset config\|profile\|all confirm` | удалить оверлей и вернуть файловые значения |
| `/export` | выгрузить эффективные настройки в чат |

### Кастомный LLM-провайдер

Бот работает с любым OpenAI-совместимым API: OpenAI, OpenRouter, DeepSeek,
Together, vLLM, Ollama, LM Studio и корпоративные шлюзы. Провайдер добавляется
из Telegram и сразу становится активным:

```text
/llm provider add openrouter https://openrouter.ai/api/v1 deepseek/deepseek-chat sk-or-...
/llm test
```

Ключ можно не указывать в команде, а задать отдельно — тогда сообщение с
ключом удаляется из чата:

```text
/llm provider add openrouter https://openrouter.ai/api/v1 deepseek/deepseek-chat
/llm provider key openrouter sk-or-...
```

Для локального сервера без авторизации:

```text
/llm provider add local http://127.0.0.1:11434/v1 qwen2.5
/llm provider nokey local on
/llm provider use local
/llm test
```

Полезные команды:

- `/llm provider list` — активный провайдер и сохранённые, без значений ключей.
- `/llm provider use openrouter` — переключить активного провайдера.
- `/llm provider use default` — вернуться к `LLM_BASE_URL`/`LLM_MODEL` из `.env`.
- `/llm provider show openrouter` — endpoint, модель, наличие ключа, заголовки.
- `/llm provider header openrouter HTTP-Referer https://example.com` — доп. заголовок (нужен OpenRouter).
- `/llm provider rm openrouter` — удалить провайдера и его ключ из `.env`.

Ключи хранятся в `.env` под именами вида `LLM_PROVIDER_OPENROUTER_API_KEY`.
Сами значения никогда не выводятся в чат. Параметры провайдеров сохраняются в
оверлее настроек и переживают рестарт сервиса.

Особенности:

- `/llm key` записывает ключ в `.env` и удаляет сообщение с ключом из чата;
  значение никогда не выводится в ответе.
- `dry_run` и `require_human_approval` меняются только с добавкой `confirm`,
  если это снимает защиту от отправки без проверки.
- Список доступных для добавления платформ ограничен реализованными
  адаптерами; произвольный сайт без адаптера парсить нечем.
- Кнопки платформ и категорий перерисовывают сообщение и сразу сохраняют
  изменение на диск.

## Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                    Telegram Bot                             │
│  (python-telegram-bot polling, отдельный asyncio task)      │
└──────────────────┬──────────────────────────────────────────┘
                   │
                   ├─ Command Handlers (/start, /status, ...)
                   ├─ Callback Handlers (inline buttons)
                   └─ Notifications (new jobs, cycle complete)
                   
                   ▼
┌─────────────────────────────────────────────────────────────┐
│                  Main Pipeline                              │
│  (continuous loop with configurable interval)               │
└──────────────────┬──────────────────────────────────────────┘
                   │
                   ├─ collect() → 7 platforms
                   ├─ dedupe → category filter → score
                   ├─ generate messages → LLM/fallback
                   └─ deliver_job() → Telegram (личные фильтры)
```

**Два параллельных процесса:**
1. **Telegram bot** — polling для команд, inline buttons, уведомления
2. **Pipeline** — непрерывный цикл сбора (с паузами, управляемыми через Telegram)

## Deployment на VPS

### systemd service

Создайте `/etc/systemd/system/freelance-bot-telegram.service`:

```ini
[Unit]
Description=Freelance Bot with Telegram Control Panel
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=freelance-bot
Group=freelance-bot
WorkingDirectory=/opt/freelance-bot
Environment="PYTHONUNBUFFERED=1"
Environment="PYTHONIOENCODING=utf-8"
EnvironmentFile=/opt/freelance-bot/.env

# Run bot with Telegram integration
# (--top у команды telegram больше нет; интервал ограничен 600-3600 с)
ExecStart=/opt/freelance-bot/venv/bin/python -m freelance_bot.cli telegram \
    --interval 600

Restart=on-failure
RestartSec=10s

MemoryMax=1.5G
CPUQuota=150%

NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/freelance-bot/var

StandardOutput=journal
StandardError=journal
SyslogIdentifier=freelance-bot-telegram

[Install]
WantedBy=multi-user.target
```

**Запуск:**

```bash
sudo systemctl daemon-reload
sudo systemctl enable freelance-bot-telegram.service
sudo systemctl start freelance-bot-telegram.service

# Проверка статуса
sudo systemctl status freelance-bot-telegram.service

# Логи
sudo journalctl -u freelance-bot-telegram.service -f
```

## Troubleshooting

### Бот не отвечает на команды

**Проверка:**

```bash
# Логи бота
sudo journalctl -u freelance-bot-telegram.service -n 100

# Проверка токена
curl -X GET "https://api.telegram.org/bot<TOKEN>/getMe"
```

**Ожидаемый ответ:**
```json
{"ok":true,"result":{"id":1234567890,"is_bot":true,"first_name":"Freelance Bot",...}}
```

### Уведомления не приходят

**Проверка:**

1. Убедитесь, что бот запущен и polling активен:
   ```bash
   sudo systemctl status freelance-bot-telegram.service
   # Должно быть "active (running)"
   ```

2. Проверьте, что есть новые подходящие заказы:
   ```bash
   # В логах должно быть "Cycle complete: ... eligible=N"
   sudo journalctl -u freelance-bot-telegram.service -n 50 | grep eligible
   ```

3. Проверьте Chat ID:
   ```bash
   # В .env должен быть правильный ID
   cat /opt/freelance-bot/.env | grep TELEGRAM_ADMIN_CHAT_IDS
   ```

### Inline кнопки не работают

**Причина:** CallbackQueryHandler не зарегистрирован.

**Решение:** Проверьте, что в логах есть:
```
Telegram bot started, polling for updates
```

Если нет — перезапустите сервис:
```bash
sudo systemctl restart freelance-bot-telegram.service
```

## FAQ

### Можно ли использовать несколько админов?

Да, укажите несколько Chat ID через запятую:

```bash
TELEGRAM_ADMIN_CHAT_IDS=123456789,987654321,555666777
```

### Можно ли использовать группу вместо личного чата?

Да, добавьте бота в группу и укажите отрицательный Chat ID группы:

```bash
TELEGRAM_ADMIN_CHAT_IDS=-1001234567890
```

### Как отключить уведомления, но оставить команды?

В коде закомментируйте вызов `telegram_bot.deliver_job()` в `pipeline.py`.

Или добавьте в конфиг:

```yaml
telegram:
  notifications: false
```

(Требует реализации этой опции в коде.)

### Можно ли запустить бота без Telegram?

Да, используйте старую команду:

```bash
python -m freelance_bot.cli run --interval 600
```

Telegram-модуль не загружается, если не вызвана команда `telegram`.
