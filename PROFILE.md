# Профиль исполнителя

Файл `profile.yaml` описывает вас: навыки, опыт, стиль письма и стратегию ценообразования. На основе этих данных LLM анализирует каждый заказ и пишет первое письмо.

---

## Зачем это нужно

Требование к системе: **все заказы, прошедшие фильтр, приходят в Telegram, и для каждого LLM пишет первое письмо на основе встроенных навыков**. Профиль — это и есть «встроенные навыки».

Без профиля LLM не знает, кто вы, и пишет generic-письма. С профилем он:

- сошлётся только на **релевантные** навыки, а не на весь список;
- упомянет конкретный опыт, который резонирует с задачей;
- посчитает цену по выбранной вами стратегии;
- будет писать в вашем тоне и длине.

---

## Структура файла

```yaml
name: ""                    # Имя или ник. Пусто — писать без подписи.
experience_years: 3
location: "Россия"

skills:                     # Основные навыки — попадают в письмо
  - Python
  - Telegram Bot API
  - FastAPI

secondary_skills:           # Дополнительные — подставляются при совпадении
  - Docker
  - PostgreSQL

experience_summary: |       # 1-2 предложения о вашем опыте
  Разработал более 20 Telegram-ботов...

pricing:
  strategy: "markup"        # minimum | markup | llm_estimate
  markup_percent: 1.0       # 1.0 = бюджет, 1.15 = +15%, 1.3 = +30%
  min_acceptable_rub: 5000  # Ниже этой суммы письмо не готовится
  hourly_rate_rub: 2000     # Для стратегии llm_estimate
  include_price_in_message: false  # Называть ли цену прямо в письме

message_style:
  tone: "friendly"          # professional | friendly | casual
  length: "medium"          # short | medium | long
  mention_portfolio: true
  ask_questions: true
  max_emoji: 0
  banned_phrases:           # Фразы, которые guard вырежет из письма
    - "готов предложить"
    - "под ключ"

availability:
  hours_per_week: 20
  immediate_start: true
  preferred_duration: "any"

communication:
  preferred_platforms:
    - telegram
    - email
  typical_response_hours: 2
```

---

## Стратегии ценообразования

### `minimum` — минимальная цена

```
цена = max(бюджет_заказчика × 0.95, min_acceptable_rub)
```

Берёте чуть ниже бюджета заказчика — максимальная конверсия в отклик. Подходит, если важно забрать заказ, а не максимизировать доход.

### `markup` — наценка (по умолчанию)

```
цена = max(бюджет_заказчика × markup_percent, min_acceptable_rub)
```

Классический подход: заказчик сам назвал бюджет, вы добавляете свой процент. `markup_percent: 1.0` — ровно по бюджету, `1.15` — плюс 15%, `1.3` — плюс 30%.

Если бюджет не указан, цена = `min_acceptable_rub`.

### `llm_estimate` — оценка LLM

```
цена = max(estimated_hours × hourly_rate_rub, min_acceptable_rub)
```

LLM оценивает трудоёмкость задачи в часах (`estimated_hours`), вы задаёте ставку. Если LLM не смог оценить часы, цена считается по бюджету заказчика.

---

## Где применяется цена

Цена рассчитывается всегда и показывается в Telegram-уведомлении:

```
*Цена по стратегии:* 17 250 ₽ (наценка)
```

Но **в тексте письма** цена появляется только если `include_price_in_message: true`. По умолчанию письмо спрашивает бюджет — это обычно работает лучше: заказчик часто называет сумму в ответе, и вы можете ответить с конкретикой.

---

## Порог минимальной цены

`min_acceptable_rub` — жёсткий фильтр. Если расчётная цена ниже порога:

- письмо **не генерируется**;
- заказ всё равно приходит в Telegram (без письма);
- в логах: `skip <uid>: price 3000 below floor`.

Это защита от копеечных заказов, на которые выгодно потратить время только на отклик.

## Навыки в письме

Письмо упоминает **только те навыки, которые соответствуют домену задачи**. Это ключевое правило: в веб-заказе вы должны выглядеть веб-разработчиком, а не «человеком, который знает Python».

### Как определяется домен

По сигналам самого заказа (заголовок, описание, теги):

| Домен | Признаки | Навыки в письме |
|-------|----------|-----------------|
| `web` | вёрстка, лендинг, HTML, CSS, React, Figma | HTML/CSS, JavaScript, React, Vue.js |
| `telegram` | бот, Telegram, чат-бот | Telegram Bot API, Python, интеграции |
| `parsing` | парсинг, сбор данных, выгрузка | Парсинг данных, Веб-скрейпинг |
| `backend` | Django, FastAPI, REST API, база | Django, FastAPI, PostgreSQL, REST API |
| `data` | SQL, база данных, ETL | PostgreSQL, SQL |
| `devops` | Docker, деплой, Linux, Nginx | Docker, Nginx, CI/CD |
| `automation` | интеграция, API, автоматизация | Интеграция с API, Автоматизация |
| `ai` | LLM, GPT, нейросети | LLM, GPT, AI-инструменты |
| `design` | дизайн, макет, логотип | Дизайн, Figma, Photoshop |
| `text` | текст, перевод, копирайтинг | Тексты, переводы |

### Как отбираются навыки

Три сигнала складываются в оценку:

1. **Где найден навык** — заголовок (4 балла) > описание (3) > теги площадки (1).
   Теги часто шумные: площадка может пометить лендинг словом «python».
2. **Принадлежность к домену** — навык из домена задачи получает +2.
3. **Жёсткое отсечение** — навык, который **не встречается в тексте заказа** и принадлежит другому домену, отбрасывается.

Пример: заказ «Сверстать лендинг», в тегах площадки стоит `python`, в профиле есть и `Python`, и `HTML/CSS`:

```
Домен: web
Навыки: HTML/CSS, JavaScript, React
```

`Python` отброшен — он не упомянут в тексте заказа и принадлежит домену `backend`.

А для заказа «Разработка Telegram-бота»:

```
Домен: telegram
Навыки: Telegram Bot API, Python, Интеграция с API
```

### Составные навыки

`HTML/CSS` распадается на `HTML` и `CSS`, `Telegram Bot API` — на `Telegram Bot API`, `Telegram Bot` и `Telegram`. Так навык совпадает с заказом, где часть названия написана по-русски («телеграм-бота»).

### В LLM-режиме

Отобранные навыки и домен передаются в prompt отдельным блоком с запретом упоминать навыки из других доменов. Модель не может «придумать» навык, которого нет в профиле.

### В fallback-режиме (без LLM)

Навыки подставляются автоматически:

```
По опыту: HTML/CSS, JavaScript, React.
```

## Как проверить профиль

```powershell
python -m freelance_bot.cli profile
```

Выведет таблицу со всеми параметрами, опытом и запрещёнными фразами.

Путь к другому файлу:

```powershell
python -m freelance_bot.cli profile --path my_profile.yaml
```

## Управление из Telegram

Профиль доступен и из бота:

| Команда | Действие |
|----------|----------|
| `/profile` | Показать навыки, опыт и стиль |
| `/pricing` | Выбрать стратегию цены (кнопки) |
| `/markup 1.15` | Установить коэффициент наценки |
| `/minprice 8000` | Установить минимальную цену |

Изменения действуют до перезапуска процесса. Чтобы сохранить их постоянно, внесите те же значения в `profile.yaml`.

---

## Рекомендации по заполнению

**Навыки — 8-15 штук.** Больше — модель начинает путаться и упоминать нерелевантное. Только то, что вы действительно готовы делать.

**`experience_summary` — 1-2 предложения.** Пишите конкретно: «20 ботов с интеграцией платежей», а не «ответственный разработчик». Конкретика = доверие.

**`banned_phrases` — ваши личные табу.** Guard вырежет их из письма перед отправкой и попросит LLM переписать. Если какая-то фраза звучит для вас неестественно — добавьте её сюда.

**`include_price_in_message`** — оставьте `false` на старте. Называя цену в первом письме, вы теряете возможность узнать реальный бюджет заказчика в ответе.
